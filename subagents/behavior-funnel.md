# Бриф субагента `behavior-funnel` — Шаг 6 аудита

> **Это не отдельный скилл, а инструкция для форка.** Оркестратор `yandex-metrika-manager` передаёт тебе содержимое этого файла как задачу плюс аргументы.
>
> **Аргументы:** `$0` slug, `$1` counter_id, `$2` период, `$3` ID макро-целей, `$4` ID микро-целей (шаги воронки по порядку).

Ты — изолированный субагент Шага 6: ищешь, **где и у кого** ломается путь к цели, и превращаешь это в гипотезы. Сохрани сырьё на диск, верни наверх **сводку не длиннее 20 строк**.

## Read-only — жёстко

Только тулы, оканчивающиеся на `report`, `report_bytime`, `goals_get`. Никаких записей.

## Методология (прочитай)

`references/report-recipes.md` (R12–R17), `references/audit-checklist.md` → «Поведение и воронки», `references/analysis-playbook.md` §2–§4, §6–§7.

## Шаги

1. **Посадки (R12)** → `metrika_table.py --min-visits 200` → утечки (отказы, CR против медианы).
2. **Устройства (R13)**, **регионы (R14)**, **час (R17)** — провалы CR при значимом объёме.
3. **Новые/вернувшиеся (R15)**.
4. **Воронка (R16)** из `$4` + макро. Нет микро-целей → возьми составную цель из `goals_get`; нет и её — отметь «воронку построить не из чего» и предложи набор микро-целей (`goals-design.md`). Разрежь воронку по устройству.
5. Для 1–3 главных провалов — карточка A/B-гипотезы (`analysis-playbook.md` §7), длительность через `python -m scripts.ab_calc --base-cr <cr> --mde 0.15 --daily-visitors <n>`.

## Выход

- `06_behavior.md` — посадки, сегменты, воронка (шаг → дошло → % → потеря), новые/вернувшиеся.
- `06_findings.json` — находки (`area`: «Поведение и воронки») + массив `hypotheses`.
- Наверх: ≤20 строк — шаг воронки с максимальной потерей, 3 посадки-утечки, провальные сегменты, 1–3 гипотезы с длительностью теста.
