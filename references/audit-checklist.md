# Чек-лист аудита Метрики с порогами

Пороги — стартовые эвристики, не законы. Каждая находка в отчёте несёт **число, период, объём и порог**. Меньше ~100 визитов в сегменте или меньше ~10 достижений цели — «мало данных», не находка.

Серьёзность: 🔴 **ломает данные или обучение Директа** — чинить первым; 🟠 **искажает выводы** — чинить в ближайший цикл; 🟡 **гигиена / рост**; ⚪ мало данных.

---

## Экспресс-санити (Шаг 0.5 режима Анализа — 3 вызова)

1. Роботы: `report({ metrics: ["ym:s:visits"], dimensions: ["ym:s:isRobot"] })` (или метрика `ym:s:robotPercentage`). Больше 10% → предупредить первой строкой.
2. Макро-цель: `goals_get({ stats_days: 30 })` → у макро-цели есть достижения и CR в правдоподобном коридоре (см. «Цели»).
3. Семплирование: в ответе ключевого отчёта признак семплирования → повторить с `accuracy: "full"`.

---

## Паспорт (Шаг 1)

| Проверка | Как | Флаг |
|---|---|---|
| Статус счётчика / кода | `counter_get` | не Active / код не найден на сайте → 🔴 |
| Нет визитов за 7 дней | отчёт `ym:s:visits` | 0 у живого сайта → 🔴 счётчик не стоит |
| Зеркала | `fields: ["mirrors"]` + отчёт по `ym:s:startURLDomain` | трафик идёт с домена, которого нет в зеркалах (поддомен, старый домен, лендинг) → 🟠 |
| Фильтры | `fields: ["filters"]` | нет фильтра своих IP при заметной доле визитов из офиса/от разработчиков → 🟡; нет фильтрации роботов при доле роботов >10% → 🟠 |
| Операции | `fields: ["operations"]` | нет вырезания мусорных параметров (`yclid`, `gclid`, сессионные id) при раздробленных страницах в отчёте → 🟡 |
| Вебвизор / карты | `counter_get` (настройки кода) | выключен → 🟡 (нечем смотреть причины на посадках) |
| Часовой пояс | `counter_get` | не совпадает с бизнесом → 🟡 (дни и часы «съезжают») |
| Доступы | `fields: ["grants"]` | лишние доступы ушедших подрядчиков, нет второго владельца → 🟡 |
| Несколько счётчиков на один сайт | `counters_get({ search: домен })` | два активных счётчика → 🟠 (какой источник правды? Директ на какой смотрит?) |

## Качество данных (Шаг 2)

| Проверка | Рецепт | Порог / флаг |
|---|---|---|
| Доля роботов | R1 | больше 5% — 🟡, больше 10% — 🟠, всплески по дням в 2+ раза к медиане — 🔴 подозрение на бот-атаку/скликивание |
| Роботы по источникам | R1 + `lastsignTrafficSource` | роботы концентрируются в `ad` → 🔴 скликивание, сигнал для Директа (РСЯ-площадки) |
| Отказы по источникам | R2 | отказы источника больше 2× медианы по сайту при объёме >300 визитов → 🟠 (боты, нерелевантный трафик или битая посадка) |
| Чужие домены входа | R3 | любой домен не из зеркал (тест-стенд, localhost, чужой сайт с вашим кодом) → 🟠 нужен фильтр |
| Самопереходы | R4 | свой домен среди сайтов-источников больше 1% визитов → 🟠 рвётся сессия (кросс-домен, платёжный шлюз, редирект http→https/www) |
| Прямые заходы | R2 | больше 40% визитов у сайта с активной рекламой → 🟠 теряются метки/реферер (редиректы, мессенджеры, приложения) |
| Разрывы | `report_bytime` по визитам, `group: day` | день с нулём или падением больше 70% к соседним при нормальной рекламе → 🔴 счётчик слетал (релиз сайта) |
| Семплирование | признак в ответе | ключевые отчёты семплированы → пометка в ограничениях |

## Цели (Шаг 3)

Источник: `goals_get({ stats_days: 30 })` + визиты за те же 30 дней → `scripts/goals_health.py`.

| Класс | Правило | Серьёзность |
|---|---|---|
| **Мёртвая** | 0 достижений за 30 дней при визитах > 500 | 🟠; если это макро-цель или цель Директа — 🔴 |
| **Шумная** | CR цели больше 30% (или больше 15% для типа «заявка/покупка») — срабатывает почти у всех | 🟠; если в стратегии Директа — 🔴 (Директ учится на мусоре) |
| **Подозрительно редкая** | макро-цель с CR меньше 0,1% при заметном трафике и живых продажах | 🟠 сверить с CRM: недосчёт? |
| **Дубли** | одинаковые условия у двух целей | 🟡 |
| Нет макро-цели | ни одной цели «заявка/покупка/звонок» | 🔴 |
| Нет составной цели | есть шаги воронки, но нет `step` | 🟡 |
| Нет ценности | у макро-целей `default_price` пуст | 🟡 (нельзя считать ценность каналов) |
| Хаос в названиях | авто-названия, «Цель 1», латиница вперемешку | 🟡 |
| «Мягкие» цели как результат | `number` / `visit_duration` используется как конверсия в Директе | 🟠 |
| Цель-URL на общей странице | условие `contain` по слишком общему куску (`/`, `?`, `order`) | 🟠 шумная по устройству |

Коридоры правдоподобия CR (визиты → цель), для ориентира: заявка с формы 1–8%, звонок/клик по телефону 0,5–5%, покупка e-com 0,5–4%, «в корзину» 3–15%, мессенджер 0,5–5%. Вне коридора — не ошибка автоматически, но повод проверить условие.

## Разметка и источники (Шаг 4, форк `traffic-sources`)

| Проверка | Порог / флаг |
|---|---|
| Реклама без UTM | доля визитов `ad` без `utm_source` больше 10% → 🟠 (кроме Директа с автометкой yclid — тогда смотрим, размечены ли остальные рекламные системы) |
| Разнобой написания | один источник в разных регистрах/вариантах (`yandex`/`Yandex`/`ya`) → 🟠 рвёт сводные отчёты |
| Нестандартный `utm_medium` | не из словаря `cpc, cpm, cpa, email, social, referral, organic, banner, display, messenger, push, sms, influencer, partner` → 🟡 |
| `utm_campaign` без системы | id и имена вперемешку, пустые, `{campaign_id}` не подставился → 🟠 |
| Классификация каналов | мессенджеры/соцсети/email попадают в «Прямые» или «Ссылки» → 🟡 (нужна разметка) |
| Объём vs качество | канал с долей визитов больше 10% и CR макро-цели меньше 0,3× от среднего → 🟠 находка «объём без качества» |

## Связка с Директом (Шаг 5, форк `direct-bridge`)

| Проверка | Порог / флаг |
|---|---|
| Директ не связан | `direct_clients_get` пусто, а реклама в Директе идёт → 🔴 (нет расходов в Метрике, нет `ym:ad:*`) |
| Потеря клик → визит | `1 − ym:ad:visits / ym:ad:clicks` больше 20% по кампании → 🟠, больше 35% → 🔴 (медленная посадка, редиректы, код счётчика ниже по странице, мобильная посадка падает) |
| Кампания без конверсий | расход больше 2× целевого CPA и 0 достижений макро-цели → 🔴 |
| CPA по Метрике vs KPI | больше 1,5× KPI → 🟠 |
| Фразы-утечки | фраза Директа с визитами больше 50 и отказами больше 60% → 🟡 (кандидат в минус — передать в `yandex-direct-audit`) |
| Поиск vs сети | отказы РСЯ больше 2× поиска при сопоставимом объёме → 🟡 норма для РСЯ до ~1,5×, дальше — площадки |
| Расхождение конверсий Директ ↔ Метрика | разные модели атрибуции — это не ошибка; называть модели словами |

## Поведение и воронки (Шаг 6, форк `behavior-funnel`)

| Проверка | Порог / флаг |
|---|---|
| Страница входа-утечка | визиты больше 200 и отказы больше 1,5× медианы посадок или CR в 2+ раза ниже среднего → 🟠 |
| Мобильный провал | CR мобильных меньше 0,5× десктопа при доле мобильных больше 40% → 🟠 (форма/скорость на мобильных) |
| Регион-провал | регион с долей больше 10% визитов и CR меньше 0,5× среднего → 🟡 (гео, доставка, нерелевант) |
| Обрыв воронки | шаг, на котором теряется больше 70% дошедших, при объёме больше 100 на входе в шаг → 🟠 — главный кандидат на A/B |
| Новые vs вернувшиеся | CR вернувшихся больше 3× новых → 🟡 рост через ретаргетинг (сегмент) |
| Время суток / дни | CR в часы/дни ниже 0,5× среднего при значимом объёме → 🟡 передать в корректировки Директа |
