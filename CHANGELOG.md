# Журнал изменений

Версии — [semver](https://semver.org/lang/ru/). Описание для пользователей — `docs/releases/`.

## 1.1.1 — 2026-10-09

**Скилл снова виден в Claude Code.** Описание для пользователей —
[`docs/releases/v1.1.1.md`](docs/releases/v1.1.1.md).

- **Шапка `SKILL.md` — валидный YAML.** Описание без кавычек содержало «: » («качества данных:
  настройки…»), строгий YAML принимал это за новый ключ. Claude Code писал в лог
  `Failed to parse YAML frontmatter` и грузил скилл без описания — модель его не видела и сама не
  вызывала. Описание взято в двойные кавычки, текст не менялся.
- **Защита от повтора:** `make_bundle.py` не собирает архив, если значение в шапке без кавычек
  содержит «: »; тест разбирает шапку строгим YAML (PyYAML, если установлен).

## 1.1.0 — 2026-10-09

**Открытый репозиторий, установка плагином Claude Code и сообщение о новой версии.** Описание для
пользователей — [`docs/releases/v1.1.0.md`](docs/releases/v1.1.0.md). Режимы и шаги не менялись.

- **Лицензия Apache-2.0** (`LICENSE`), как у остальных скиллов ai-hub-open: репозиторий открывается.
- **Плагин:** `.claude-plugin/plugin.json`, скилл ставится из маркетплейса `ai-hub-open/claude-plugins`.
- **`VERSION`** + **проверка версии** один раз за разговор, до mode-gate: скилл сверяет `VERSION` с
  `main` на GitHub и, если вышла новая, говорит, как обновиться. Без сети молча идёт дальше. Файлы сам
  не заменяет.
- **Рабочая папка — вне папки скилла.** В разделе Scripts явно: `metrika/<slug>/` живёт в текущей
  папке пользователя, скрипты (запуск из корня скилла) получают абсолютные пути. Плагин при обновлении
  заменяет свою папку целиком — данные клиента там бы пропали.
- **`scripts/make_bundle.py`** — сборка `yandex-metrika-manager.zip`: одна папка верхнего уровня, ровно
  один `SKILL.md`, обязательные файлы на месте; не попадают `.env`, `metrika/`, `tests/`, CI, манифест
  плагина, кеши и `.git` (в т. ч. файл `.git` из git worktree). Три теста в `tests/test_scripts.py`.
- **`.gitignore`**: `.env`, рабочая папка `metrika/`, кеши, сборки.
- **CI:** `.github/workflows/version-check.yml` сверяет версию в `plugin.json`, `VERSION`, верхней записи
  `CHANGELOG.md` и в теге релиза.
- Пример имени коннектора `MetrikaDevadent` заменён нейтральным `MetrikaClient`.
- README: установка плагином и в Claude Desktop, состав, лицензия.

## 1.0.0 — 2026-10-08

Первый релиз: аудит, анализ и управление Яндекс Метрикой через коннектор Метрики.

- Три режима в одном скилле: **аудит** (по умолчанию, read-only), **анализ** (read-only), **управление**
  (цели и сегменты, запись под гейтом с журналом и откатом).
- Оркестратор в `SKILL.md`, форки `traffic-sources`, `direct-bridge`, `behavior-funnel`.
- Скрипты на стандартной библиотеке: `metrika_table`, `goals_health`, `utm_hygiene`, `ab_calc`,
  `changes_log`, `render_report`; тесты без сети.
