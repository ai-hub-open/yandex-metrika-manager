# yandex-metrika-manager

> Аудит, анализ и управление Яндекс Метрикой через подключение к Метрике (MCP). Три режима в одном скилле.

Скилл превращает ИИ-агента в веб-аналитика: агент проверяет, можно ли верить данным счётчика, отвечает
на вопросы по данным — откуда трафик, почему упали заявки, во что обходится заявка по кампаниям Директа —
и заводит цели и сегменты для ретаргетинга.

- **Аудит** (по умолчанию, только чтение) — можно ли верить данным: паспорт счётчика, качество данных, цели,
  UTM-разметка, связка с Директом, поведение на сайте → HTML-отчёт «починить / проверить / норма».
- **Анализ** (только чтение) — ответ на вопрос по данным или регулярный разбор (неделя или месяц к прошлому
  периоду): поиск причины от симптома — источник → страница входа → устройство → регион → шаг воронки,
  гипотезы для A/B-тестов, ТЗ разработчику.
- **Управление** — запись в счётчик: цели и сегменты. Агент показывает проект изменений и предпросмотр,
  записывает только после вашего явного «ОК», ведёт журнал с возможностью отката и проверяет, что новая цель
  начала срабатывать.

Режим скилл выбирает сам по вашей просьбе; если неясно — спросит одним вопросом. В режимах аудита и анализа
агент в счётчик не пишет никогда.

Правка кампаний Директа — не здесь: аудит и ведение — [yandex-direct-audit](https://github.com/ai-hub-open/yandex-direct-audit),
создание — [yandex-direct-manager](https://github.com/ai-hub-open/yandex-direct-manager).

## Что на выходе

| Режим | Результат |
|---|---|
| Аудит | `АУДИТ_МЕТРИКИ_<проект>.html` — находки по приоритету, у каждой число, период и порог; сводка в чат |
| Анализ | ответ в чат на 5–10 строк и файл с таблицами (`.md` / `.csv`); при регулярном разборе — `pulse.md`, по которому следующий разбор сравнивает период с прошлым |
| Управление | журнал изменений `changes_log.jsonl` (было / стало) и отчёт `change_report.md`; для целей на JS-событиях — ТЗ разработчику |

Рабочая папка `metrika/<проект>/` создаётся в текущей папке.

## Подключение к Метрике

Скилл работает через MCP-сервер Метрики, размещённый на стороне click.ru: разворачивать ничего не нужно,
в Claude добавляется только адрес подключения.

1. **Выберите способ доступа и соберите адрес.**

   | Способ | Адрес | Что нужно |
   |---|---|---|
   | Через click.ru, все аккаунты | `https://metrika-mcp.aihub.click.ru/c/<токен click.ru>` | токен click.ru и подключённая Метрика в click.ru |
   | Через click.ru, один аккаунт | `https://metrika-mcp.aihub.click.ru/c/<токен click.ru>/<аккаунт>` | то же; `<аккаунт>` — логин Яндекса или ID интеграции Метрики в click.ru |
   | Напрямую в Яндекс, без click.ru | `https://metrika-mcp.aihub.click.ru/y/<OAuth-токен Яндекса>` | OAuth-токен Яндекса с доступом к Метрике |

   - **Токен click.ru** — профиль [click.ru/userinfo.html](https://click.ru/userinfo.html) → поле
     **API Token** → скопировать или **Создать**. «Пересоздать» — только при утечке: старые подключения
     перестанут работать.
   - **Метрика в click.ru.** Для адресов с `/c/` аккаунт Яндекса с Метрикой должен быть подключён
     в интеграциях click.ru ([инструкция](https://help.click.ru/97#connect-yandex-metrica)). Иначе агент
     получит ответ «не подключена Яндекс Метрика».
   - Логин с `@` или пробелом в адресе кодируется: `@` → `%40`, пробел → `%20`.

2. **Добавьте подключение в Claude.**
   - Claude Desktop / claude.ai: **Settings → Connectors → Add custom connector** → любое имя (например,
     `yandex-metrika`) → адрес → **Continue** → **Add**, затем перезапустите Claude Desktop.
   - Claude Code:

     ```
     claude mcp add --scope user --transport http yandex-metrika "<адрес подключения>"
     ```

3. **Проверьте.** Попросите агента «покажи мои счётчики Метрики» — он вызовет `yandex_metrika_counters_get`
   и покажет список с номерами и сайтами.

⚠️ **Адрес подключения равносилен паролю:** токен в нём открывает рекламные кабинеты и Метрику этого аккаунта
click.ru. Не пересылайте его и не вставляйте в общие чаты; при утечке пересоздайте токен в профиле click.ru.

**Для записи нужны права.** Аудит и анализ работают с доступом на просмотр. Создавать и менять цели
и сегменты можно только в счётчике, к которому у аккаунта есть доступ на редактирование. Если сервер запись
не принимает, агент прямо скажет об этом и внесёт операцию в отчёт как ручную работу в интерфейсе Метрики.

## Установка

Скилл ставится из каталога плагинов [claude-plugins](https://github.com/ai-hub-open/claude-plugins) — там же
выбор способа установки ([какой способ выбрать](https://github.com/ai-hub-open/claude-plugins#какой-способ-установки-выбрать))
и включение автообновления.

**Claude Desktop — через интерфейс.** На вкладке **Code**: кнопка **+** рядом с полем ввода → **Plugins** →
**+ Add → Add marketplace** → `ai-hub-open/claude-plugins` → **Sync** → на вкладке **Discover** нажмите
**Add** у `yandex-metrika-manager`.

**Claude Code — командами:**

```
/plugin marketplace add ai-hub-open/claude-plugins
/plugin install yandex-metrika-manager@ai-hub-open
```

Автообновление включается один раз: `/plugin` → **Marketplaces** → `ai-hub-open` → **Enable auto-update**;
без него — `/plugin marketplace update ai-hub-open`.

**Архивом (claude.ai, любой тариф).** Скачайте `yandex-metrika-manager.zip` из блока **Assets**
[последнего релиза](https://github.com/ai-hub-open/yandex-metrika-manager/releases/latest) (или соберите:
`python -m scripts.make_bundle`). Включите **Settings → Capabilities → Code execution and file creation**
и загрузите архив в **Customize → Skills → + → Create skill → Upload a skill**. В архив не входят тесты,
CI, манифест плагина, `.env` и рабочие папки.

Вызов: `/yandex-metrika-manager:yandex-metrika-manager` или просьбой своими словами — «проверь Метрику»,
«откуда трафик», «настрой цели под Директ». В начале разговора скилл сверяет свою версию с GitHub и скажет,
если вышла новая.

Рабочая папка `metrika/` создаётся в текущей папке, а не внутри плагина: папка плагина при обновлении
заменяется целиком. Если раньше скилл лежал папкой в `~/.claude/skills/`, удалите её, иначе скилл
загрузится дважды.

## Ограничения

- Работает с одним счётчиком за раз.
- Не правит кампании Директа: из Метрики агент только смотрит на Директ — расход, клики, визиты, цели.
- Не ставит код счётчика и JS-события на сайт: для целей на событиях агент готовит ТЗ разработчику.
- Удаляет и меняет цели только поштучно после явного «ОК» на каждое необратимое изменение.
- Мало данных (меньше ~100 визитов в сегменте или ~10 достижений цели) — в выводе так и написано
  «мало данных», а не догадка.
- Конверсии всегда подписаны моделью атрибуции; числа из разных моделей агент не сравнивает.

## Состав

| Путь | Зачем |
|---|---|
| `SKILL.md` | маршрут: выбор режима, шаги 0–7 аудита, анализ, управление |
| `subagents/` | задания для параллельных веток аудита: источники трафика, связка с Директом, поведение и воронка |
| `references/` | карта инструментов подключения, чек-лист с порогами, рецепты отчётов, плейбук анализа, дизайн целей, правила безопасной записи, шаблон отчёта |
| `scripts/` | `metrika_table`, `goals_health`, `utm_hygiene`, `ab_calc`, `changes_log`, `render_report` (только стандартная библиотека Python); `make_bundle` — сборка архива |
| `assets/findings_example.json` | образец `findings.json` |
| `tests/` | pytest без сети — обязательная проверка перед слиянием |
| `evals/evals.json` | тест-кейсы скилла |
| `VERSION` | версия скилла — по ней он сообщает, что вышла новая |
| `.claude-plugin/plugin.json` | манифест плагина Claude Code (в архив не входит) |
